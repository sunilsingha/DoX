Set up Document AI extraction

  1. Subscribe, then create a service instance. The Document AI application is where you designed the schema. This page calls the service instance. In your subaccount, open Instances and Subscriptions, create an instance of Document Information Extraction, and create a service key.
  2. Copy the service key into default-env.json. Start from default-env.sample.json. Use uaa.url, uaa.clientid, uaa.clientsecret, and the service url. Leave this file uncommitted. On Cloud Foundry the same values are read from VCAP_SERVICES.
  3. Activate the schema, and a template if the fields are manual. Schema Configuration must show the schema as active. The first activated version is 1. Custom documents usually use setup type manual, which only returns values after you create and activate a template for a sample invoice. Put that template name in Request options.
  4. Point the columns at your export. Save the export as schema/ZSFL_GST_Invoice_schema.json, or choose Load schema export. The local file decides the table columns and the default schema name. BTP still extracts with the schema you activated there, so the names must match.
  5. Start the app and upload an invoice. Run npm install and npm start, then open the page. Choose a PDF or a single-page PNG or JPEG and press Extract invoice. The server asks XSUAA for a token, posts the file to /document/jobs, and polls GET /document/jobs/{id}?extractedValues=true until the status is DONE.
  6. Read the two tables. Header fields keep the schema order and show a confidence score. Line items are one row per extracted line. A green score is 90% or higher, orange is 75% to 89%, and red is below that. Empty cells are fields the schema asked for and the model did not return.

The request options look like this:

{
  "clientId": "default",
  "documentType": "custom",
  "schemaName": "ZSFL_GST_Invoice",
  "schemaVersion": "1",
  "templateName": "your-template"
}

Preview sample fills the tables with a fictional GST invoice so you can learn the layout before the service key works. It does not call BTP.

The service key used to be hardcoded in srv/dox.js. It is read from the environment now. Rotate that key in BTP if this repository was shared. The old trial authentication host currently returns 404, so create a service key from the subaccount you are using.
