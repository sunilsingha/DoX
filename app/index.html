Set up SAP AI Core extraction

  1. Entitle SAP AI Core on the extended plan. In the global account, open Entitlements, choose Configure Entitlements, then Add Service Plans. Select SAP AI Core and the extended plan. Generative AI Hub is not included in the free or standard plan. Assign the entitlement to this subaccount.
  2. Subscribe to SAP AI Launchpad. Add the SAP AI Launchpad entitlement and run its booster, or subscribe to it under Instances and Subscriptions. Open Launchpad with a user that has mloperations_editor or genai_manager. The service key used by this app does not need those roles. They are only for creating the deployment.
  3. Create the AI Core instance and service key. In the subaccount, create a service instance of SAP AI Core with plan extended. Create a service key and download it. Copy url, clientid, clientsecret, and serviceurls.AI_API_URL into default-env.json using the names in default-env.sample.json. Leave that file uncommitted. The instance creates a resource group named default. Use that unless you created another group.
  4. Deploy a vision-capable chat model. In SAP AI Launchpad, select this AI Core runtime and the default resource group. Open ML Operations, then Scenarios, and confirm foundation-models is listed. If it is missing, the instance is not on the extended plan. Create a configuration: scenario foundation-models, the executable for the provider (for GPT models this is azure-openai), parameter modelName gpt-4o, and modelVersion latest. Create a deployment with duration Standard. Wait until the status is RUNNING. Copy the deployment ID into AICORE_DEPLOYMENT_ID. Deploy the model itself. An orchestration-only deployment is a different endpoint and is not what this page calls. One deployment serves only the modelName on its configuration. To switch models from this page, create another configuration for each model, such as gpt-4o-mini or gpt-4.1, and deploy that too. The Model menu lists only RUNNING chat deployments and calls the one you pick. GPT models use executable azure-openai. Gemini chat models use executable gcp-vertexai with a model such as gemini-2.5-flash. Undeployed models, embedding models, and realtime models are not listed.
  5. Keep one schema file per document type. SAP AI Core does not store Document AI schemas. Put each export in the schema folder, for example schema/ZSFL_GST_Invoice_schema.json. The Schema menu lists those files. Choosing one loads its header and line-item fields. Add a letter-of-credit export the same way, with Load schema export or as another JSON file. The same model is used. Only the field list in the prompt changes.
  6. Extract. Run npm install and npm start, then open the page. Choose AI Core, Document AI, or Both. Both sends the same file to each service and marks fields that disagree. With AI Core or Both, the Model menu chooses which running deployment reads the invoice. Configured deployment uses AICORE_DEPLOYMENT_ID. Test connection checks the selected source. Document AI also needs DOX_UAA_URL, DOX_UAA_CLIENTID, DOX_UAA_CLIENTSECRET, and DOX_URL in default-env.json. Put the activated template name in Request options when the schema fields use manual setup. A PDF is sent to AI Core. A photo or scan should be PNG or JPEG. TIFF is not accepted by the vision model.
  7. Read the two tables. Header fields stay in schema order. Line items are one row per extracted line. The confidence score is the model's own estimate, from 0 to 1. Green is 90% or higher, orange is 75% to 89%, and red is below that. An empty cell means the model did not find that field on the document.

The call looks like this:

POST {AI_API_URL}/v2/inference/deployments/{deploymentId}/chat/completions?api-version=2023-05-15
AI-Resource-Group: default
Authorization: Bearer <token>

Preview sample fills the tables with a fictional GST invoice so you can learn the layout before the service key works. It does not call SAP AI Core.
